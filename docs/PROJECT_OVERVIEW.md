# SeasonForge — Обзор архитектуры и функционала проекта

> **SeasonForge** — это узкоспециализированный трекер сезонов, лиг и эвент-таймлайнов для главных ARPG-игр (Path of Exile 1/2, Diablo IV, Last Epoch, Torchlight: Infinite).
> Проект функционирует как гибрид **Data-Driven SSG (Static Site Generation)**, **PWA (Progressive Web App)** и **клиентского SPA**, сочетая автоматический сбор данных через ИИ с двуэтапной модерацией в Telegram и моментальной отдачей статического контента.

---

## 1. Назначение и поддерживаемые игры

Приложение отображает актуальное состояние текущих сезонов, обратные отсчёты до новых стартов, фазы PTR-тестирований, интерактивный архив исторических сезонов, ленту анонсов/новостей (Event Feed) и глобальную хронологическую шкалу (Timeline).

### Поддерживаемые игры:
1. **Path of Exile 1** (Grinding Gear Games) — полная история с лиг 2013 года (40+ сезонов)
2. **Path of Exile 2** (Grinding Gear Games)
3. **Diablo IV** (Blizzard Entertainment) — история с Сезона 1
4. **Last Epoch** (Eleventh Hour Games) — история циклов с 1.0
5. **Torchlight: Infinite** (XD Inc.) — история с S1

## 3. Автоматизированное обновление данных и Модерация

Обновление данных происходит в защищённом автоматическом режиме с обязательным подтверждением человеком:

1. **Мониторинг новостей (`scripts/updater/adapters/`)**:
   - Каждая игра имеет собственный адаптер (`DiabloAdapter`, `PoEAdapter`, `PoE2Adapter`, `LastEpochAdapter`, `TorchlightAdapter`).
   - Адаптеры запрашивают официальные источники (RSS-ленты, Blizzard News API, Steam Web API).
   - Если ID последней новости не изменился — вызов ИИ пропускается для экономии ресурсов.

2. **Обработка через LLM (Google Gemini Flash)**:
   - В ИИ отправляется текст новых статей.
   - С помощью `responseSchema` ИИ возвращает только строго валидный JSON: даты сезонов, PTR, ключевые эвенты, статусы и списки фич на двух языках (EN / RU).

3. **Защита от сбоев и неофициальных перезаписей**:
   - **Защита официальных дат**: Если сезон имеет статус `verification: "official"`, авто-парсер не имеет права перезаписывать дату старта без официального анонса.
   - **`mergeGameData()`**: Если адаптер или ИИ не смогли распознать дату, система не затирает имеющиеся валидные данные на `TBA`.
   - **`Validator.js`**: Проверяет типы, корректность диапазонов дат, логику `startDate < endDate` и допустимость статус-кодов по whitelist.
   - **Атомарная запись (`fileUtils.js`)**: Все записи файлов выполняются через временный файл `.tmp` с последующим переименованием.

4. **Двуэтапная модерация (Telegram Bot + Cloudflare Worker)**:
   - Авто-парсер на GitHub **не публикует изменения напрямую**.
   - Найденный diff отправляется на безопасный Cloudflare Worker `/api/pending-log`.
   - Cloudflare Worker присылает сообщение в Telegram с описанием изменений и кнопками `✅ Одобрить` / `❌ Отклонить`.
   - Публикация запускается строго при клике по кнопке с авторизованного Telegram ID через `repository_dispatch`.
   - Секреты (токен бота, GitHub PAT) остаются зашифрованы в Cloudflare и не хранятся на GitHub.

## 4. Архив исторических сезонов и лиг (`data/history/`)

История всех прошедших сезонов выделена в структурированные файлы данных `data/history/{game-id}.json`:

- **Состав данных архива**:
  - Название сезона/лиги на русском и английском (`season.en`, `season.ru`).
  - Чёткие даты начала и окончания (`startDate`, `endDate`).
  - Читаемый URL-слаг (`slug`, например `league-325-settlers-of-kalguur` или `season-14`).
  - Прямые ссылки на официальные новости и патчноуты анонса (`sourceUrl`).
- **Связка с SSG и Timeline**:
  - На основе файлов архивов `build.js` генерирует отдельную статическую SEO-страницу для каждого исторического сезона.
  - Таблица истории автоматически выводится на странице каждой игры с расчётом точной длительности сезона в днях.
  - Исторические сезоны отображаются на глобальной интерактивной таймлайн-карте (`Timeline.js`).

## 5. Генератор статических страниц (SSG — `scripts/build.js`)

При каждом обновлении базы автоматически запускается сборка сайта:

- **Генерация статических HTML**:
  - Каждая игра получает собственную SEO-страничку (`/games/path-of-exile/`, `/games/diablo-iv/` и т.д.).
  - **Архивные страницы сезонов**: Каждый исторический сезон из `data/history/` компилируется в отдельную HTML-страницу (например, `/games/path-of-exile/league-325-settlers-of-kalguur/`).
  - **Лента событий**: Компилируется страница `/changelog/` (ARPG Event Feed).
- **Вспомогательные файлы**:
  - `src/data/fallback-seasons.js`: Автоматически обновляемый аварийный дамп данных для оффлайн-работы клиента.
  - `sitemap.xml` и `robots.txt`: Динамически обновляются под все существующие URL (включая страницы архивов).
- **Встроенное авто-тестирование (`validateGeneratedPages`)**:
  - Проверяет все 87+ сгенерированных HTML-файлов на наличие `<title>`, `<meta description>`, `canonical`, корректность разметки JSON-LD (Schema.org) и отсутствие битых ссылок.

## 6. Фронтенд, PWA и пользовательский интерфейс

Фронтенд написан на **чистом JavaScript (ES Modules)** без использования сторонних фреймворков.

### Ключевые возможности интерфейса:
1. **PWA & Офлайн-режим (`sw.js`, `manifest.json`)**:
   - Полная поддержка установки веб-приложения на смартфоны (Android/iOS) и ПК.
   - Кеширование статичных ассетов и страниц для работы без подключения к сети.

2. **Режимы отображения (Views)**:
   - **Card / Feed**: Карточки игр с прогресс-барами текущего сезона, таймером до следующего старта и списком ключевых фич.
   - **Timeline**: Интерактивная хронологическая шкала для визуального сравнения длительности и наложения текущих и исторических сезонов.
   - **Games Catalog & Event Feed**: Быстрая навигация по играм и лента анонсов/новостей.

3. **Динамический статус сезона (`src/utils/status.js`)**:
   - Автоматически рассчитывает фазу сезона по проценту прохождения (`just-started`, `in-progress`, `late-season`, `final-days`, `ended`).

4. **Локализация (i18n)**:
   - Полная двухъязычность (русский `ru` и английский `en`) с сохранением выбора пользователя.

5. **Интерактивные таймеры (`src/utils/countdown.js`)**:
   - Обновляет точечные текстовые узлы в DOM каждую секунду.

## 7. Структура директорий проекта

```
SeasonForge/
├── .github/workflows/       # GitHub Actions (расписание парсера + dispatch деплой)
├── assets/                  # Иконки, логотипы игр и графические ассеты
├── content/                 # Дополнительные текстовые материалы для SSG страниц
├── data/
│   ├── games.config.json    # Конфигурация игр (адаптеры, launch time, source URLs)
│   ├── seasons.json         # Главная база данных сезонов (с changelog и lastCheckedAt)
│   ├── history/             # Архивированные данные прошлых сезонов по играм
│   ├── cache/               # Локальные кэши успешных вызовов по играм
│   └── logs/                # Журнал работы авто-обновлятора (хранение 30 дней)
├── scripts/
│   ├── build.js             # Генератор статического сайта (SSG) + Валидатор
│   ├── update-seasons.js    # Оркестратор парсинга и взаимодействия с Gemini AI
│   ├── cloudflare-worker.js # Код Cloudflare Worker бота для Telegram модерации
│   └── updater/             # Адаптеры источников, Validator.js, fileUtils.js
├── src/
│   ├── app.js               # Точка входа клиентского приложения
│   ├── sw.js                # Service Worker для PWA и оффлайн-режима
│   ├── components/          # UI-компоненты (Header, Navbar, GameCard, Timeline...)
│   ├── services/            # Загрузка и кэширование данных (SeasonService.js)
│   ├── store/               # Управление состоянием (state.js)
│   ├── i18n/                # Словари и функции локализации (en.js, ru.js)
│   ├── templates/           # Шаблоны страниц для SSG (game.html, season.html)
│   └── utils/               # Утилиты (helpers, date, countdown, status, seo, analytics)
├── package.json             # Скрипты билда и обновления
└── CNAME                    # Конфигурация кастомного домена
```
